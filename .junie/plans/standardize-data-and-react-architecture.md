# Requirements

### Цель
Привести проект к единому стандарту структуры и импорта модулей, получения CMS-данных, React-интерактивности и пользовательских состояний загрузки, сохранив текущую Astro SSG-архитектуру и SEO.

### Объём
- Общий типизированный API-клиент и единый React-hook `useApi()` на TanStack Query для интерактивных React-компонентов, без повторения деталей HTTP-запросов по страницам.
- Согласованный контракт API и единая курсорная пагинация для всех страниц сборки и интерактивных каталогов.
- Определённые правила размещения файлов, импорта, границ Astro/React и загрузочных/ошибочных/пустых состояний.
- React использовать для сложных интерактивных компонентов; статические страницы и контентные шаблоны остаются Astro, если нет причины для интерактивности.

### Вне объёма
- Замена CMS или создание собственного backend/хранилища.
- Перевод сайта на SPA или отказ от SSG.
- Редизайн и изменение пользовательск��х функций фильтрации/поиска, кроме улучшения загрузки, ошибок и пагинации.

### Критерии приёмки
- Все CMS-запросы используют единый API-клиент с `BACKEND_API` и `BACKEND_KEY`, заголовком `X-Api-Key` и согласованным маршрутом API.
- Нет расхождения, при котором страницы вызывают одностраничный `fetchPosts()`, а пагинация существует только в отдельной функции; материалы не теряются при превышении одной страницы CMS.
- Каталог и страницы материалов продолжают генерироваться как индексируемый SSG HTML; сложные интерактивные UI работают в React-islands.
- Во время первоначальной загрузки и смены страницы/фильтра видны подходящие состояния; ошибки и пустые результаты имеют отдельное понятное представление.
- OpenSpec фиксирует структуру, правила импортов, единый источник API-логики, React/TanStack границу и тестируемые сценарии.

# Technical Design

### Текущее устройство и подтверждённые проблемы
- `package.json`: Astro `^7.3.6`; React и `@tanstack/react-query` не подключены.
- `src/lib/cms.ts`: `fetchPosts()` получает только одну страницу по `/v1/content/posts`; `fetchPostsByParams()` уже содержит cursor-loop с пределом 50 страниц; `requestJson()` формирует запросы отдельно. `BACKEND_API` ожидается как полный base URL, поэтому фактический URL зависит от конфигурации окружения.
- `src/pages/index.astro`, `src/pages/materials/index.astro` и `src/pages/materials/[slug].astro` получают CMS-данные на сборке; `getStaticPaths()` формирует статические маршруты из результата `fetchPosts()`.
- `src/lib/catalog-client.ts` филь��рует уже отрендеренные карточки на клиенте. UI состоит из Astro-компонентов `src/components/FilterBar.astro`, `MaterialCard.astro`, `SearchBox.astro`, `SiteNav.astro`; общий каркас — `src/layouts/BaseLayout.astro`.
- `openspec/changes/add-mvp-home-catalog/design.md` закрепляет Astro SSG, CMS как источник истины и клиентские URL-фильтры. Его требования сохраняются.
- Критические пункты для спецификации: единообразно определить `BACKEND_API` (текущий код соединяет его с `/v1/...`, а OpenSpec описывает `/api/v1/...`), подключить пагинацию в сборке и избежать дублирования API-контракта в Astro и браузере.

### Архитектурное решение
Гибрид SSG + TanStack Query: общий API-клиент отвечает за transport, URL и типизацию; build-time код Astro вызывает его для статического контента и маршрутов; React-islands используют общий клиент через `useApi()`/TanStack Query для интерактивных данных, состояний и пагинации. Это сохраняет HTML/SEO и ограничивает клиентский JavaScript интерактивными компонентами.

Предусмотреть React integration Astro и совместимые версии `react`, `react-dom`, `@astrojs/react`, `@tanstack/react-query`; точные версии определить при реализации с проверкой совместимости. Не использовать `useApi()` непосредственно в `.astro` frontmatter: это React hook, а серверный build-time путь должен вызывать общий API-клиент.

### Файлы и границы изменений
- `astro.config.mjs`, `package.json`, `package-lock.json`: интеграция React и зависимости TanStack Query.
- `src/lib/cms.ts` либо выделенные `src/lib/api/*`: единая реализация запросов, контракты ответа, обработка ошибок и pagination primitives; стра��ицы не формируют URL/headers самостоятельно.
- Новые React provider/hooks в `src/components/react/` или согласованной общей структуре: один `useApi()` с типизированными query keys и обёрткой над `useQuery`/`useInfiniteQuery`; реестр QueryClient ограничен браузерным island и не шарится между серверными запросами.
- `src/pages/index.astro`, `src/pages/materials/index.astro`, `src/pages/materials/[slug].astro`: использовать общий API-клиент при генерации; передавать только необходимые данные/начальное состояние React-компонентам.
- Сложные интерактивные фильтры/поиск/список и пагинацию постепенно вынести в React-islands; простые карточки и статическая разметка могут остаться Astro.

### Контракт загрузки и UI
- `useApi()` принимает уникальный query key и функцию/описание endpoint, возвращает типизированные данные, ошибку, `isPending`/`isFetching` и средства повторной загрузки или перехода по cursor.
- Использовать semantics TanStack Query v5: первоначальная загрузка, фоновая загрузка/смена query и ошибка не смешиваются; кнопка во время своей операции показывает локальный busy-state, блокирует повторную отправку и имеет доступное имя.
- Для пагинации CMS использовать `next_cursor`; контролировать завершение и ошибки, не терять уже полученные страницы при догрузке. Ограничение на максимальное число страниц должно быть явным и сопровождаться диагностикой, а не молча выдавать неполный каталог.
- Для каталога определить skeleton/initial loading, кнопку «Загрузить ещё» или иной единый UI пагинации, отдельные empty/error/retry-состояния; сохранить поисковую строку и фильтры в URL согласно текущим требованиям.

### Проверки и ограничения
Изменение затрагивает конфигурацию сборки, загрузку данных и клиентские islands; соблюдать проектное ограничение OpenSpec о коротких файлах (в предыдущем дизайн-документе — до 150 строк) и разбивать модули по ответственности. Секреты не включать в браузерный код: там допустим только public key; значения переменных не логировать.

# Delivery Steps

###   Step 1: Зафиксировать стандарты и API-контракт в OpenSpec
OpenSpec описывает единые правила модульной структуры, импортов и границ Astro/React, а также согласованный контракт CMS API.
- Добавить отдельную change-спеку в существующем `openspec/changes/` формате: proposal, capability spec, design и tasks согласно `spec-driven`.
- Описать канонический формат `BACKEND_API`, `X-Api-Key`, типы запросов/ответов и единый API-клиент, сверив URL с официальной CMS-документацией перед реализацией.
- Указать конкретные текущие места интеграции: `src/lib/cms.ts`, страницы `src/pages/*` и повторяющийся transport-код.

###   Step 2: Подключить React-islands и стандартизировать доступ к данным
Сборка и интерактивные острова используют общий API-клиент при сохранении SSG.
- Подключить совместимую с Astro React integration и TanStack Query, зафиксировать версии lock-файлом.
- Определить отдельные build-time функции клиента и React `useApi()` hook с query keys, типами, error contract и безопасным жизненным циклом QueryClient.
- Перевести CMS-потребителей страниц `index.astro`, `materials/index.astro`, `materials/[slug].astro` на общий transport без прямого создания API URL в страницах.
- Перенести сложные интерактивные компоненты в React-islands, оставив статический контент Astro.

###   Step 3: Внедрить полноценную курсорную пагинацию CMS
Каталог и генерация маршрутов получают полн��й опубликованный набор материалов без потери страниц.
- Свести одностраничный `fetchPosts()` и cursor-loop `fetchPostsByParams()` к ясным функциям общего API-клиента.
- Использовать `next_cursor` для всех build-time потребителей и пагинацию TanStack (`useInfiniteQuery` или эквивалент) там, где данные догружаются в браузере.
- Установить явное поведение предельного числа страниц, частичного отказа и повторной попытки; обеспечить сохранение результатов уже успешных запросов.
- Проверить построение `/materials/<slug>/` для записей с последующих страниц CMS.

###   Step 4: Добавить единые loading/error/empty состояния и проверки
Кнопки, списки и страницы дают согласованную обратную связь при загрузке, ошибке и отсутствии данных.
- Создать переиспользуемые UI-паттерны для локального busy-state кнопок, первоначальной загрузки, фоновой загрузки/догрузки, ошибки с повтором и пустого результата.
- Подключить состояния к каталоговым React-islands и синхронизировать фильтрацию/поиск с URL без регрессии текущего UX.
- Проверить `npm run check`, `npm run build`, SSG/SEO, многостраничные ответы CMS, URL-фильтры, ошибки и блокировку повторных запросов.
