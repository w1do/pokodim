## Context

Мотивация и объём — в `proposal.md`, требования — в `specs/home-page/spec.md` и `specs/material-catalog/spec.md`. Стек для MVP: **Astro (SSG)**. Управление данными — через CMS платформы **backend.w1do.ru** (документация `https://backend.w1do.ru/LLM.txt`; инструменты — MCP cms-pokodim и admin API): проект `pokodim`, локаль `ru`, план «Старт»; сервис `content` на проекте сейчас выключен, включает его `services_toggle`; public-ключ проекта выпускается только в консоли оператором. Жёсткие ограничения предпочтений: файлы кода ≤ 150 строк, CI push → выкат ≤ 10 минут.

## Goals / Non-Goals

**Goals:**

- Каталог материалов из CMS backend.w1do.ru, отрендеренный в статические HTML-страницы и индексируемый поисковиками (SEO).
- Фильтры по инструменту и уровню сложности + поиск, работающие в URL.
- Тёмная тема с акцентным цветом, единая для всех страниц.
- Быстрый CI: сборка (включая чтение CMS) и проверка укладываются в минуты, кэш зависимостей по lock-файлу.

**Non-Goals:**

- Личный кабинет, покупки, подписка, оплата (отдельные changes позже).
- Своя модель хранения, база данных или админка: данные живут в CMS, управление — её инструментами (консоль, MCP cms-pokodim, admin API).
- Автоматическая пересборка сайта при изменении контента (webhook/cron) — отдельный change.
- Пользовательские комментарии, аккаунты, авторизация.

## Decisions

**D1. Генератор статики — Astro (SSG), данные читаются из CMS на сборке.**
Материалы читаются из публичного API CMS при сборке: на выходе статический HTML с реальным контентом для SEO, нулевая стоимость рантайма и никаких запросов к API в браузере для рендеринга. Альтернативы: Next.js (SSR) — избыточен для каталога статей и тяжелее в CI; рантайм-фетч в браузере — хуже для SEO и зависит от доступности API у посетителя.

**D2. Хранение и управление данными — CMS backend.w1do.ru.**
Модель данных: материал = пост (`posts_create` → `posts_publish`, тело — Markdown в `body`/`blocks`); инструмент = категория (`categories_create`, входит в адрес через `primary_category_id`); уровень сложности = тег (создаётся при создании поста); подборка на главной = `is_featured`; описание карточки = `seo.description`, фолбэк — лид из `body` (состав `PostResource` уточнить при реализации). Наполнение — MCP cms-pokodim (`categories_*`, `posts_*`, `seo_*`) или admin API. Сайт читает публичный API: `GET /api/v1/content/posts` (курсорная пагинация, фильтры `locale`, `category`, `tag`) и `GET /api/v1/content/posts/{slug}` ключом `X-Api-Key` (public; CORS в браузер открыт). Пререквизиты: включить сервис `content` (`services_toggle`) и выпустить public-ключ в консоли оператором. Альтернативы: коллекции (`collections/entries` — типизированные поля и `filter[...]`) — фича тарифа, вне плана отвечают 402, отложены; Markdown-файлы в репозитории — заменены по решению пользователя: управление данными через backend.w1do.ru.

**D3. Фильтры и поиск — клиентские, состояние в URL query-параметрах.**
Полный каталог рендерится на сборке как статический список, небольшой клиентский скрипт фильтрует карточки и синхронизирует состояние с `URLSearchParams`. Это даёт поведение из спеки (фильтры в URL, переживают перезагрузку) без сервера. Публичный API не отдаёт полнотекстового поиска по контенту — поиск клиентский по заголовку и описанию; серверные параметры `category`/`tag` доступны, но каталог для MVP мал и фильтруется целиком на клиенте. Альтернативы: отдельные страницы на каждый фильтр — раздувают сборку; server-side фильтрация — несовместима со SSG.

**D4. Структура — композиция коротких компонентов и layout'ов.**
Ограничение ≤ 150 строк на файл: разметка страницы собирается из мелких компонентов (`MaterialCard`, `FilterBar`, `SearchBox`, `Hero`, `SiteNav`), стили — глобальный CSS-файл темы + локальные стили. Никаких UI-фреймворков — Astro + ванильный CSS достаточно для каталога карточек.

**D5. Маршрутизация.**

- `/` — главная.
- `/materials/` — каталог.
- `/materials/<slug>/` — страница материала: `getStaticPaths` из списка постов CMS на сборке, slug страницы = slug поста; неизвестный slug → `404.html`.

**D6. CI — GitHub Actions (или CI хостинга), сборка + валидация ≤ 10 минут.**
Шаги: установка по lock-файлу с кэшем → `astro check` (типизация) → сборка с запросом к backend.w1do.ru (baseUrl и public-ключ — секреты CI; запросы единичны, на время не влияют). Деплой — статика на хостинг проекта. Кэш `node_modules` по `package-lock.json` — требование предпочтений по CI ≤ 10 минут.

## Risks / Trade-offs

- [Контент в CMS меняется после сборки — на сайте старые данные до следующей пересборки] → для MVP ручная или плановая пересборка; автоматический триггер (webhook/cron) — отдельный change.
- [Сервис `content` выключен, public-ключ выпускается только в консоли] → prereq-задачи до наполнения и сборки; проверка `services_list` и `api_keys_list`.
- [Описание карточки зависит от состава `PostResource`] → фолбэк на лид из `body`; состав ответа API проверить при реализации.
- [Коллекции недоступны вне тарифа (402)] → материалы на постах, категориях и тегах; коллекции — при миграции позже.
- [Клиентская фильтрация загружает весь каталог в страницу] → для MVP каталог мал (< 100 материалов); при росте перейти на разбиение на страницы — не меняет поведение из спеки.
- [Нет автотестов UI в MVP] → валидация на уровне типов (`astro check`) и ручная проверка сценариев спеки; интерактивные тесты Playwright можно добавить позже без изменения спеков.
- [404 для несуществующего slug при SSG] → Astro генерирует `404.html`; хостинг должен отдавать его с кодом 404 — проверить при деплое.

## Migration Plan

Наполнение CMS (категории, посты, SEO) выполняется до первой сборки сайта через MCP cms-pokodim или admin API; CMS — источник истины, данные переживают откат кода. Откат сайта — предыдущая сборка статики; отдельной миграции данных нет.

## Open Questions

- Хостинг и домен покодим.рф (не влияет на спеки и структуру задач — решается отдельно при деплое).
- Акцентный цвет: зелёный или фиолетовый — выбрать при реализации UI, оба допустимы спекой.
- Триггер пересборки при изменении контента (ручно, cron или webhook) — решается после первых публикаций; на спеки и набор задач MVP не влияет.
